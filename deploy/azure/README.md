# Развёртывание Finder в Microsoft Azure

Одна виртуальная машина Linux с Docker Compose: контейнер Finder (сайт + Hermes) и Caddy,
который сам получает и продлевает HTTPS-сертификат. Образ собирается прямо на машине из
исходников, которые скрипт копирует по SSH — локальный Docker и реестр образов не нужны.

## Что создаётся

| Ресурс | Зачем |
|---|---|
| Виртуальная машина Ubuntu 24.04, диск 64 ГБ | сайт, Hermes, общий браузер |
| Публичный IP + имя `finder-xxxx.<регион>.cloudapp.azure.com` | адрес сайта |
| Сеть и правила: открыты 80 и 443; SSH (22) — только для IP компьютера, с которого идёт деплой | |

Цена зависит от размера машины и региона — проверьте в калькуляторе Azure. `Standard_B2s`
(2 ядра, 4 ГБ) хватает для демонстрации и нескольких пользователей; `Standard_B2ms` (8 ГБ) —
запас для ~10 одновременных.

### Подписка Azure for Students

- Разрешены не все регионы (проверить: `az policy assignment list`). На момент первого деплоя
  нужные размеры машин были доступны только в **`denmarkeast`**.
- Квота — 4 ядра серии B на регион: одна машина B2s/B2ms помещается.
- Кредит 100 $ расходуется, пока машина включена. Остановить без удаления данных:
  `az vm deallocate -g finder-rg -n finder-vm`, включить: `az vm start -g finder-rg -n finder-vm`.

## Перед началом

1. Подписка Azure, роль Contributor или Owner.
2. Azure CLI: <https://aka.ms/installazurecliwindows>, затем:

```bash
az login
```

## Развернуть

Из корня проекта, в PowerShell:

```powershell
.\deploy\azure\deploy.ps1 -ResourceGroup finder-rg -Location denmarkeast -VmSize Standard_B2s -InviteCode "придумайте-код"
```

Первый запуск идёт 25–35 минут (создание машины, установка Docker, сборка образа). В конце
печатается адрес сайта.

| Параметр | Что делает |
|---|---|
| `-InviteCode` | регистрация на сайте только с этим кодом (рекомендуется: сайт открыт всему интернету) |
| `-CloseRegistration` | полностью закрыть регистрацию |
| `-VmSize` | размер машины |
| `-CustomDomain` | свой домен (A-запись должна указывать на IP машины до запуска) |
| `-SshSourceAddress` | с какого адреса разрешён SSH; по умолчанию — текущий IP этого компьютера |
| `-ContactEmail` | e-mail для «вежливого» доступа к PubMed и OpenAlex |

## Обновить после изменений в коде

```powershell
.\deploy\azure\deploy.ps1 -ResourceGroup finder-rg -UpdateOnly -InviteCode "тот-же-код"
```

Заново загружает исходники, пересобирает образ (несколько минут: слои кэшируются) и
перезапускает сайт. Данные сохраняются — они в томе `finder-data` на диске машины.
Параметры настроек (`-InviteCode`, `-CloseRegistration`, `-ContactEmail`) применяются при каждом
запуске: не указанный код приглашения означает «без кода».

## Логи и состояние

```bash
ssh -i ~/.ssh/finder_azure azureuser@<IP> "cd /opt/finder && sudo docker compose ps && sudo docker compose logs --tail 80 finder"
```

Проверка: `https://<адрес>/api/health` → `{"ok": true, ...}`.

## Резервные копии

Каждую ночь в 03:30 машина сохраняет архив всех данных в `/opt/finder/backups` (7 последних).
Это копия на том же диске — для защиты от потери машины включите Azure Backup или копируйте
архивы в Storage Account.

## Подписки моделей

Каждый пользователь подключает свои на странице «Акаунти»: ChatGPT/Codex, Nous, xAI, MiniMax
(код устройства), Claude Pro/Max и **Google Gemini (Antigravity)** (ссылка → вставить код).
Gemini доступен только здесь, на Linux: сессия Google хранится в домашней папке профиля каждого
пользователя.

## Известные ограничения

- Некоторые сайты блокируют адреса дата-центров Azure (пример: `eu.siteground.com` отдаёт 403
  даже настоящему браузеру). Агент тогда ищет информацию в других источниках. Обойти можно
  только внешним прокси: `FINDER_PROXY_URL=http://user:pass@host:port` в `/opt/finder/.env`.
- Сервер работает в одном экземпляре; масштабирование — увеличением размера машины.

## Безопасность

- Порт приложения 8000 доступен лишь Caddy внутри Docker; внутренний адрес общего браузера
  (`/internal/*`) закрыт снаружи.
- Секретный ключ сессий генерируется на машине при первом запуске (`/opt/finder/.env`, права 600).
- Токены подписок пользователей лежат в томе `finder-data`. Доступ к машине = доступ к ним.
- SSH-ключ администратора: `~/.ssh/finder_azure` на компьютере, с которого шёл деплой.

## Удалить всё

```bash
az group delete --name finder-rg --yes
```

Удаляет машину, диск с данными и адрес — без возможности восстановления.
